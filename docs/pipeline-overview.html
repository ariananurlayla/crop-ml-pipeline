The CropHarvest Pipeline, End to End

Point-level crop-type classification over a global open benchmark: 10,610 field points, four classes (Rice / Corn / Sugarcane / Other), 216 features per point built from 18 bands × 12 months of Sentinel-1, Sentinel-2, ERA5 and SRTM data — trained as a 1D temporal CNN against three tabular baselines, and evaluated under a spatially-grouped split so every reported number reflects generalisation to geographies the model never saw.

01Data

The data source is NASA CropHarvest (Tseng et al., NeurIPS Datasets & Benchmarks 2021; Zenodo record 10251170 v14, CC-BY-SA-4.0) — a global, open benchmark of point-level crop labels collected by crowdsourced and institutional interpretation. Our run draws from 16 source datasets spanning Canada, France, Germany, Uzbekistan, Mali, Kenya, Tanzania, Uganda, Zimbabwe, Brazil, Martinique and Réunion, plus globally scattered JECAM and croplands.org points (lat −25°…56°, lon −123°…108°). Every point is stored as an HDF5 array of shape (12, 18): 12 monthly timesteps over 18 bands.

Flattened for the tabular side, each band×month becomes one named column (VV_Jan … NDVI_Dec) → 216 features per point. Unlike the IFRI CSV, there is no separate static-vector block: all 18 bands ride along the monthly axis, so the CNN input tensor is [B, 18, 12].

02Preprocessing

  1. Fetch & verify. cropharvest_data.py downloads features.tar.gz (78.7 MB) and labels.geojson (81.7 MB) from Zenodo, streaming to temporary files with size + md5 checks and atomic rename — an interrupted download can never be mistaken for a complete one. Extraction is path-traversal-guarded and marked complete by a marker file, so reruns never redo it.
  2. Filter labels. Drop is_test rows (their arrays live in a separate archive) and rows with null classification_label (binary-only labels). What remains is the labelled crop pool.
  3. Map to 4 classes. Raw label strings are casefolded and looked up in CROPHARVEST_LABEL_MAP, with a fallback that strips “ - ” qualifiers; unmapped crops become the Other pool, sampled seeded (--other-samples 4000). Unmapped variants are printed at build time so the map can be extended.
  4. Assemble the table. Each point’s (12,18) HDF5 array is read, transposed band-major and reshaped to 216 columns; the result is cached as a CSV (16.1 MB) whose filename encodes the sampling parameters, so a different seed or sample size rebuilds rather than silently reusing a stale cache.
  5. Spatially-grouped split. Group ids are rounded 1° lat/lon cells (152 non-empty cells). A GroupShuffleSplit assigns whole cells to 80 / 10 / 10, retried with fresh seeds until every class has ≥5 samples in all three folds (else a loud stratified fallback). Result: train 8,747 / validation 695 / test 1,168 — no geographic cell is shared across folds.
  6. NaN handling. Missing months are filled with the per-column median.
  7. Normalisation. Z-score per channel, statistics fitted on the training split only and reused for validation/test — no leakage through the scaler.
Why the spatial split matters (the leakage lesson)

The same data gave the CNN 85.2% test accuracy with a random stratified split and 76.5% with the spatially-grouped one. Neighbouring points share fields, sensors and label sources; a random split leaks that correlation into the test set and inflates every metric. The honest number — and the one reported — is the spatial one.

All three consume the raw 216-column table on the same seeded split as the CNN, so every comparison is like-for-like.

CNN 1D (the deep model)

LayerShape / detail
Input[B, 18, 12] — 18 band channels over the 12-month axis
Conv blocks ×3Conv1d k=5 → 64, 128, 256 channels; each: BN + ReLU + MaxPool(2) + Dropout(0.2)
Attention (optional)4-head temporal self-attention over the monthly sequence (--attention)
PoolingGlobal average pool over time → [B, 256]
HeadFC 256 → 128 → 4 logits (or 2 in binary mode)

Why 1D convolutions over months, not 2D over images: the labels are points, so no spatial context exists to convolve over. Each point’s signal is a set of 18 time series, and the conv filters slide along the phenological axis — learning, in effect, shapes like “NDVI ramps in month 3, VV dips early” without hand-built features. The GAP makes the summary invariant to where in the season the cycle starts. Training: FocalLoss (γ=2) for class imbalance, Adam (lr 1e-3, wd 1e-4), ReduceLROnPlateau, early stopping patience 20, best checkpoint by validation loss.

4-class test accuracy, bars windowed to the 70–80% range. Macro-F1: LightGBM 78.0 · XGBoost 77.9 · RF 75.3 · CNN 77.2. Chance is 25%.

On this benchmark the gradient-boosted trees and the CNN land in the same band (76–79%). The CNN’s temporal structure is not yet the deciding factor at 10k samples — the binding constraints are label noise from heterogeneous interpretation protocols and the coarse “Other” class. The binary stage (Rice vs rest) reaches 88.9% — nearly identical to the IFRI 2024 two-class stage’s 89.29%, which anchors the replication story.

Run it

python main.py --cropharvest --task classification --epochs 150 --baseline lightgbm
python main.py --cropharvest --task classification --baseline xgboost   # or rf
python main.py --cropharvest --task classification --binary             # Rice vs rest
python main.py --cropharvest --task classification --attention          # + temporal self-attention

Everything is seed-controlled (seed 42 reproduces the exact split and metrics above); the downloaded data and the built table live in data/cropharvest/, and reruns hit the cache and go straight to training.

Data: G. Tseng, I. Zvonkov, C. L. Nakalembe, H. Kerner, CropHarvest: A global dataset for crop-type classification, NeurIPS Datasets and Benchmarks, 2021 — Zenodo record 10251170 (v14), CC-BY-SA-4.0. The pipeline also runs on the synthetic demo and the IFRI 181-column GEE CSV; the HST regression stage remains IFRI-only. Figures in outputs/run_*/figures/ use the same palette as this page.
